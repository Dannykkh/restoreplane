Read-only architectural review of `plan.md`, `spec.md`, `team-review.md`, ADR-001 through ADR-005, and `docs/domain-dictionary.md`. No files modified. No browsing.

**Critical Findings**

| Severity | Finding | References | Concrete Plan Change |
|---|---|---|---|
| Critical | Service cutover is sequenced before the durable runtime exists. `Phase 2: Windows Service and Application Boundary` exits with all backup/restore requests routed through service, but `Phase 3: Durable Dispatcher, Process Supervisor, and Recovery Point Commit` implements the queue, leases, fencing, supervisor, and reconciliation needed to make that safe. | `Phase 2` Exit Gate G0-C; `Phase 3` Work 1-12; ADR-001; ADR-003 | Split Phase 2 into “service shell only” and “execution cutover.” Move the minimum durable queue, fencing, process supervisor, and reconciliation into the cutover gate, or make Phase 3 a prerequisite for G0-C. |
| Critical | Local IPC authentication is under-specified for a privileged Windows service. “user/session 인증” is not enough for destructive restore, destination deletes, secret access, and cross-user machines. | `Phase 2` Work 3; Cross-cutting Security Gates; FR-RST-08 | Add an IPC threat-model task: named-pipe ACL/security descriptor, client SID capture via impersonation, command-level authorization, replay/duplicate request handling, per-user profile scoping, admin limitations, fuzz/oversize tests, and audit events for rejected commands. |
| Critical | Secret custody across Tauri user, service account, CLI, migration, and rollback is unresolved. A service account may not decrypt user-DPAPI secrets, while machine-wide secrets can overexpose credentials. | `Phase 1` Work 5-8; `Phase 2` Work 4; FR-CON-03; FR-MIG-01; Cross-cutting Security Gates | Add a dedicated Secret Store ADR before implementation: DPAPI scope, service account access, unlock/import flow, backup/restore of secret metadata, recovery-code behavior, secret rotation, and tests proving no plaintext in Operational Store, IPC payloads, process args, or logs. |
| Critical | Recovery Point, Snapshot, and required-destination semantics still conflict at the edge. `ADR-004` separates Recovery Point completeness from Protection Compliance, while AS-10 allows partial required-destination success. It is unclear whether such a run creates a Snapshot, is restore-eligible, or is only repairable. | ADR-004; `Phase 3` Work 8-9; FR-DSP-02; FR-SNP-07; AS-10 | Add an explicit three-gate state model: artifact completeness, replica durability, and protection compliance. | Critical | Restore-as-exec is acknowledged but not made enforceable. Logical restore can execute SQL, recreate unsafe definers, extensions, triggers, jobs, functions, or server-scope objects. “격리 또는 승인” is not an implementation plan. | FR-RST-06; FR-RST-09; `Phase 4` Work 8-9; Cross-cutting Security Gates | Add per-engine restore safety policy before G2: default new DB, least-privilege restore credentials, blocked server-scope objects by default, object inventory review, disposable target isolation requirements, network egress policy, and hard tests for dangerous fixtures. |
| Critical | Rollback after cutover is mostly a statement, not an operational playbook. **Verdict: CONDITIONAL GO**

Minimum corrections required before implementation should proceed:

1. Re-sequence service cutover so durable queue, fencing, process supervision, and reconciliation exist before all execution is routed through the service.
2. Add ADR-level detail for IPC authorization and Secret Store custody.
3. Resolve Recovery Point, partial replica, Snapshot visibility, restore eligibility, and Protection Compliance state semantics.
4. Specify SQLite WAL, transaction, checkpoint, backup/export, indexing, and contention rules.
5. Add enforceable restore safety, retention/prune safety, and post-cutover forward-recovery playbooks.
