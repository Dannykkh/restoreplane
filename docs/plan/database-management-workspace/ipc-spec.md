# Local IPC Contract — Database Management Workspace

Date: 2026-11-17. Contract v1; implementation in progress. Actual native/live evidence and remaining gaps: [checklist-status](checklist-status.md). Normative inputs: [plan](plan.md), [spec](spec.md), [dictionary v3](../../domain-dictionary-database-management.md), [team review](team-review.md).
Transport: local Tauri commands plus a command-owned small-notice Channel. Result bodies use bounded invoke pulls; no HTTP API, MCP server or general SQL in the privileged backup service.

## Composition and authority

- `restoreplane-application::WorkbenchCommand` is a separate closed enum from existing `ApplicationCommand`; one payload/result registry defines all Workbench commands below.
- Existing Tauri Builder in `apps/console/src-tauri/src/lib.rs` composes managed `WorkbenchState` and `workbench_request(request, onResult?)`; existing `service_request` remains the backup/control-plane bridge.
- Rust derives SID/logon session/integrity/app nonce/window identity from native invocation context. Request JSON cannot assert or override them; reject elevated/high-integrity Workbench before user files/DPAPI initialization.
- One current-user process owner/mutex and one journal actor serve managed windows; second process activates primary or refuses writes. Handles/cursors/reviews/streams remain window-bound.
- Workbench credentials are separately user-DPAPI protected; no service secret resolution, arbitrary SQL, parameter values or result rows pass to backup_service.
- Strict payload decoding rejects unknown fields, duplicate object keys, invalid IDs/integers, excessive nesting/body size and unsupported protocol versions before dispatch.
- Every SQL dispatch needs fresh `workbench.binding.authorize` unless that physical session holds an adapter-certified server-enforced readonly state and a valid read lease. Parser verdict alone never qualifies a lease.
- Fresh authorization is also required for COMMIT, generated edits, each import batch and protection handoff. Expiry/service failure permits local status/cancel/rollback/disconnect; it never causes auto-COMMIT or write replay.
- Authorization linearizes at the service's configuration/ownership read transaction; a later archive cannot revoke SQL already admitted/sent. It is not atomic with the remote DB or a distributed target lock.

### Sole new privileged service command

`ApplicationCommand::WorkbenchBindingAuthorize`, wire `workbench.binding.authorize`, is a read-only metadata/authority operation with no new Operational Store tables (schema remains v4).

```ts
type Id = string; type U64 = string; type Digest = string; // canonical unsigned decimal / lowercase 64-hex; algorithm defined by context
type Scope = {workspaceId:Id; connectionProfileId:Id; databaseTargetId:Id};
type AuthorizeRequest = Scope & {purpose:"connect"|"read"|"mutate"|"commit"|"protection"; expectedDescriptorRevision:Digest|null; appNonce:Id};
type RootTrust = {kind:"system"}|{kind:"custom";canonicalPath:string;contentDigest:Digest};
type ConnectDescriptor = {engine:"postgresql"|"mysql"|"mariadb"|"sqlite"; route:{kind:"tcp";host:string;port:number}|{kind:"file";canonicalPath:string}; database:{engineObjectId:string;name:string;sourceFingerprint:string}; tls:{mode:string;serverName:string|null;rootTrust:RootTrust|null}; transportOptions:Record<string,string>; expectedServerIdentity:string|null};
type TargetConflict = {kind:"backup"|"restore"|"maintenance";runId:Id;state:string};
type BindingReceipt = Scope & {descriptor:ConnectDescriptor;descriptorRevision:Digest;authorityEpoch:Id;authorizedAtMs:U64;readLeaseExpiresAtMs:U64|null;observedConflicts:TargetConflict[]};
```

- Caller is the native Workbench coordinator through existing authenticated named-pipe IPC, not an unrestricted frontend pass-through; app nonce is bound to the authenticated principal and is not a standalone bearer secret.
- Read one consistent existing Workspace/Connection/Target/secret-reference metadata snapshot; require current owner membership, active state and exact parent relations. Return no service secret ID or secret material.
- `descriptorRevision = BLAKE3("restoreplane.workbench.binding.v1\0" || canonical_json(revisionInput))`; recursive object keys sort by UTF-8 bytes, arrays retain defined order, absent optionals become explicit null, integers are canonical decimal strings, strings retain exact validated Unicode bytes. No locale-dependent normalization.
- `revisionInput` enumerates: schema tag; Workspace ID/owner/active/archive state; profile ID/workspace/engine/transport/exact host/port/file path/sourceResourceKey/TLS mode; complete validated connect-affecting adapter configuration; target ID/workspace/profile/engineObjectId/canonical case-preserving database name/normalized name/sourceFingerprint/active state; current service auth-reference ID/purpose/state/fingerprint metadata; TLS expected hostname/root-trust kind/custom canonical path+content digest; tunnel/proxy route and authentication-reference metadata when supported; expected observed server identity. Secret bytes never enter this input/output.
- Hash the complete validated adapter configuration internally, returning only an allowlisted nonsecret descriptor; an unknown route/TLS/auth/connect-affecting key disables the capability instead of silently ignoring it. Display aliases may be returned separately and are not connection authority.
- No stored revision counter is invented. `authorityEpoch` is existing service boot identity. If v4 metadata cannot establish an enumerated required proof, return `WB_BINDING_UNPROVEN`; do not add authority tables or silently guess.
- Custom root CA bytes are checked against the declared content identity when read; user engine verifies the same bytes before TLS. Read transaction does not make mutable filesystem/DNS/server state atomic; peer identity/file identity is rechecked on the actual opened connection.
- Any revision mismatch returns `WB_BINDING_STALE`; any currently observed conflict refuses new mutating admission as `WB_TARGET_BUSY` with bounded conflict IDs. Receipt is observational and cannot exclude a later service/other-client operation.
- Read lease maximum proposed 30s, memory-only, bound to principal/app/window/scope/revision/authorityEpoch and the certified readonly connection. Service restart/revision invalidation retires it. No cached authorization for unsafe/unknown SQL.

## Common request, error and pagination types

```ts
type Request<C extends keyof Commands> = {protocolVersion:1;requestId:Id;command:C;payload:Commands[C][0];attemptToken?:string};
type Reply<T> = {ok:true;requestId:Id;data:T}|{ok:false;requestId:Id;error:WBError};
type WBError = {code:string;messageKey:string;retryable:boolean;operationId:Id|null;field:string|null;details:{reason?:string;conflictId?:Id;conflictingOperationIds?:Id[];expectedVersion?:U64;actualVersion?:U64}};
type PageInput = {cursor:string|null;limit:number};
type Page<T> = {items:T[];nextCursor:string|null;completeness:"complete"|"limited";count:{kind:"unknown"}|{kind:"estimate"|"exact";value:U64};asOfMs:U64};
type SessionRef = {sessionId:Id;connectionGeneration:U64};
type ObjectRef = {catalogId:Id;schemaVersion:Digest};
type Limits = {maxRows:number;maxBytes:number;statementTimeoutMs:number;lockWaitMs:number};
type Admission = {operationId:Id;version:U64;deduplicated:boolean};
```

- Decimal-string U64 is mandatory for counts, versions and sequences; JS number is reserved for checked bounded budgets/indices, never unrestricted SQL integer data.
- All paged lists default 100, maximum 200 entries and 512KiB encoded response; stable total ordering and cursor filter/owner binding are server-owned. No offset-until-exhaustion accumulation helper.
- Cursors are opaque memory handles bound to owner/window/scope/revision/schema/filter/order/generation; tampering, expiry or mismatch returns `WB_CURSOR_INVALID`/`WB_RESULT_EXPIRED`, never a broader query.
- No stable unique order yields one bounded unordered preview and `nextCursor:null`; count is not automatically exact. Keyset is live-per-page unless an explicit certified snapshot handle is attached.
- `retryable` permits repeating safe status/read admission, not resubmitting SQL. A response timeout after accepted execution must use operation.get with the original identity.
- Error codes: `WB_PROTOCOL_UNSUPPORTED`, `WB_PAYLOAD_INVALID`, `WB_FORBIDDEN`, `WB_ELEVATED_UNSUPPORTED`, `WB_BINDING_UNPROVEN`, `WB_BINDING_STALE`, `WB_AUTH_EXPIRED`, `WB_SERVICE_UNAVAILABLE`, `WB_TARGET_BUSY`, `WB_CAPABILITY_UNSUPPORTED`, `WB_SESSION_STALE`, `WB_CURSOR_INVALID`, `WB_RESULT_EXPIRED`, `WB_LIMIT`, `WB_ROW_CONFLICT`, `WB_ATTEMPT_EXPIRED`, `WB_IDEMPOTENCY_CONFLICT`, `WB_JOURNAL_UNAVAILABLE`, `WB_STATEMENT_REJECTED`, `WB_OUTCOME_UNKNOWN`, `WB_CANCEL_UNSETTLED`, `WB_ACK_INVALID`, `WB_IO`.
- `WB_STATEMENT_REJECTED` carries no raw driver error and requires native protocol completion plus an observed transaction state; cached flags/ErrorResponse alone do not establish it. Confirmed normal database failure may require rollback on the same held connection. Unknown/external effects and unsettled cancellation remain uncertain. Edit conflicts reuse `WB_ROW_CONFLICT` with only opaque conflictId; capability refusals use `WB_CAPABILITY_UNSUPPORTED` with a bounded closed reason.
- Driver text/SQLSTATE may be held as bounded sanitized diagnostics; credentials/SQL/parameters/rows are absent from default errors/logs/support bundles. Unknown outcome always has `retryable:false`.

## Typed cells, pages and stream envelopes

```ts
type Cell = {kind:"null"}|{kind:"bool";value:boolean}|{kind:"i64"|"u64"|"decimal";value:string;scale?:number}|{kind:"float";value:string}|{kind:"text";value:string}|{kind:"bytes";base64:string}|{kind:"temporal";value:string;typeName:string;offset:string|null;precision:number}|{kind:"unsupported";typeName:string;reason:string}|{kind:"large";valueHandle:Id;typeName:string;byteLength:U64;preview:string};

```

- Float string is canonical finite round-trip decimal or `NaN`/`Infinity`/`-Infinity`; decimal preserves exact precision/scale; temporal retains engine semantics. JSON null, empty text and SQL NULL differ.
- A large/unsupported/display-truncated cell is never editable; `result.value.get` defines an explicit bounded chunk-read capability, not a promise every LOB can fit memory. Current native drivers do not issue Large handles and refuse this uncertified capability; oversize cells are refused at the existing64KiB bound. Native row handles are invalid after result/schema/session retirement.
- Proposed gates: 512 columns; 64KiB inline cell; 256KiB encoded stream envelope (schema/control also bounded); 8MiB outstanding credit; 32MiB JS page LRU; 64MiB native result buffers. Huge schema uses bounded metadata pages or explicit unsupported error.
- Reserve encoded credit before enqueue/serialization; budget decoded heap, copies and retained metadata separately. One exceptional giant frame cannot bypass the maximum.
- Rust records sent sequence->encoded byte charge; ACK can advance only through actually sent contiguous sequences. Duplicate/stale ACK releases zero; future/wrong-owner/wrong-generation/overflow refuses; byte charges retire once.
- Receiver deduplicates applied sequence. Attach validates retention and subscribes to notices; `result.frames(afterSequence)` pulls retained original envelopes. Absent retained data returns expired. Replay reuses its original credit charge, never grants double credit and never reexecutes SQL.
- Channel carries only `ResultNotice`, serialized below1KiB, with no schema/row bodies. This avoids Tauri's large-Channel global payload cache when a window does not fetch or is destroyed. Native retains the charged frame before notifying; a notice alone does not advance the sent ledger.
- `result.frames` returns at most one frame with the full reply bounded at256KiB. The internal envelope allowance reserves at least1KiB for the reply wrapper and checks the actual serialized full reply. At most one pull per stream is active. Serialization/copy reservations and the pull permit survive through response serialization/return. Actual frame pull advances only contiguous sent sequences; ACK cannot acknowledge a mere notice. Duplicate replay retains sequence/encodedBytes and consumes bounded transport memory without a second credit grant.
- `result.attach` may return `{attached:false,terminal:ResultEnvelope|null}` after row retention expires. That small terminal is status-only, never a delivered frame: consume its completeness/error without advancing applied sequence, sent ledger or ACK and do not force a row pull. `result.frames` remains expired and never reexecutes SQL. Normal retained terminals still arrive in sequence through frames. A hint can be duplicated/lost; explicit attach/pull recovers only retained data. A FramePull that expires during serialization must fail mark_sent and return the bounded error rather than release an expired body.
- Terminal/control has reserved capacity outside row credit plus a hard bounded control budget; zero ACK expires/cancels reads. Terminal state is also pull-queryable if Channel delivery fails.
- Channel ordering is not durable delivery, frontend render completion or a memory-credit protocol; both Channel and pull reads use the same ownership/accounting rules.

## Session, operation and transaction responses

```ts
type Mode = "read_only"|"read_write"|"full";
type Session = SessionRef & Scope & {descriptorRevision:Digest;mode:Mode;executionEpoch:U64;state:"connecting"|"ready"|"busy"|"retiring"|"closed";actualContext:{endpoint:string;database:string;role:string;purpose:"source"|"restored"};capabilities:Record<string,{supported:boolean;reason:string|null}>};
type StatementOutcome = {ordinal:number;transactionId:Id|null;digest:Digest;outcome:"not_sent"|"sent"|"succeeded"|"failed"|"cancelled"|"outcome_unknown";effectClass:"read"|"write"|"ddl"|"transaction"|"unknown";effectEvidence:"none"|"read_only"|"pending_transaction"|"committed"|"rolled_back"|"outcome_unknown";rowsMatched:U64|null;rowsChanged:U64|null;version:U64;errorCode:string|null};
type Transaction = {transactionId:Id;session:SessionRef;state:"opening"|"active"|"failed_needs_rollback"|"commit_requested"|"committed"|"rollback_requested"|"rolled_back"|"outcome_unknown";isolation:string;readOnly:boolean;idleExpiresAtMs:U64};
type Operation = {operationId:Id;version:U64;kind:"query"|"manual_transaction"|"verified_apply"|"import_job"|"import_batch"|"export_job"|"protection_link";state:"accepted"|"dispatching"|"running"|"commit_requested"|"committed"|"rolled_back"|"failed"|"outcome_unknown"|"completed"|"cancelled"|"interrupted"|"partial";effectSummary:"none"|"read"|"transactional"|"partial"|"unknown";transactionOutcome:"none"|"open"|"commit_requested"|"committed"|"rolled_back"|"outcome_unknown";resultCompleteness:"none"|"complete"|"capped"|"cancelled"|"interrupted"|"partial";transactionId:Id|null;statements:StatementOutcome[];parentOperationId:Id|null;batchIndex:number|null;acknowledgedAtMs:U64|null;createdAtMs:U64;updatedAtMs:U64};
type Intent = {[C in "query.run"|"transaction.commit"|"edit.apply"|"import.start"|"import.continue"]:{command:C;payload:Commands[C][0]}}["query.run"|"transaction.commit"|"edit.apply"|"import.start"|"import.continue"];
type PreparedAttempt = {attemptToken:string;expiresAtMs:U64;payloadDigest:Digest};
```

- Statement outcomes may be paged through operation.statements; operation.get embeds only a bounded current window, never an unbounded script vector. Scripts use parser-certified reviewed boundaries; inseparable procedural blocks are one unit with conservative effect scope.
- Proposed statement30s/lock2s/snapshot60s/manual-idle30s settings are adapter-certified hypotheses. Expiry triggers explicit cleanup, never invented rollback evidence.
- Query completion is distinct from its containing transaction outcome; an autocommit script can be partial even if its final statement failed.
- Statement `succeeded` inside an open transaction has `effectEvidence:pending_transaction`, never committed until positive commit evidence. Reads/export/import parents use completed/cancelled/interrupted/partial as appropriate, not fictional write commits. Unknown effects override reassuring read/job labels.
- Cancel includes expected Execution Epoch and query identity; native coordinator serializes late cancellation with completion and next-run admission. Unsettled cancel retires the socket; write-bearing transaction becomes unknown absent rollback proof. No next run uses that socket.

## Admission, durability, data requirements and existing protection commands

- Insert uses the explicit EditChange insert arm and does not require an existing rowHandle. Omitted columns are reviewed as server defaults/generated values and must satisfy catalog nullability/default capability; generated columns cannot be supplied. UPDATE DEFAULT is initially unsupported; SQL NULL is an explicit null cell. No default/omit intent is inferred from an empty display string. Draft/typed-original storage is bounded at proposed512KiB and review response at1MiB; oversized edits reject or require an explicit smaller separately reviewed batch, never silently truncate/split atomic intent.
- Conflict errors carry only an opaque conflictId in allowlisted details. Raw current rows remain excluded from errors/journal/logs. `edit.conflict.get` returns only observations actually captured during that failed native apply and labels observedAtMs/currentSchemaVersion; it does not fetch current DB state. Original/draft remain the immutable review basis. Missing row, unavailable/unproven observation and present typed values are distinct; unavailable is never inferred from display text. TTL/eviction/stale owner/window/session/generation refuses the handle, preserves the user draft and requires a separately explicit fresh browse/new review for a new basis. Observed conflict values are not a real-time guarantee.
- Each conflict row's changeIndex is the unique0-based immutable EditReview.changes index (bounded below the reviewed change count); native checks its corresponding rowHandle, including null for inserts. Multiple inserts are never paired by a shared null handle or guessed row order. If the failing batch cannot identify a particular change/current row, report unavailable observations without inventing that association.

- `operation.prepare` stores metadata digest/token only, binds native owner/window/scope/command/review/JournalEpoch/BootEpoch, and issues an expiring native attempt token (proposed24h). It never saves plaintext SQL/parameters for restart replay.
- I=yes admission atomically records attempt scope+digest+operation/version before dispatch. Same token/digest returns existing operation; different digest conflicts; expired/foreign epoch may query an existing record but never admit anew. Sent/unknown writes never transfer execution on claim expiry.
- Kind mapping is normative: query.run->query; transaction.commit updates its manual_transaction operation; edit.apply->verified_apply; import.start->import_job with import_batch children; export.start->export_job. Non-write jobs also receive native internal admission keys; absence of caller attemptToken never permits duplicate target-write dispatch.
- Manual transaction begin durably creates its operation before BEGIN; commit's native attempt binds that existing transaction/operation and a guarded commit_requested edge, not a second remote execution or mutable replacement of its original admission digest. Repeated commit returns its current outcome, never sends COMMIT again after dispatch uncertainty.
- Query source/drafts are volatile unless explicitly saved encrypted. Restart invalidates reviews/sessions/cursors and retires unsent intents; dispatched writes without positive evidence become unknown. Metadata retention proposed30days with uncertainty/tombstones/quota rules in [db-schema](db-schema.md).
- Explicit read_only mode may use closed native `BEGIN READ ONLY`/hold verification/one unchanged user statement/cleanup controls outside a manual transaction; preserve server-default isolation and disclose this statement scope in review. This is connection policy, not SQL-buffer rewriting or an undisclosed script-wide transaction. Existing manual readonly transactions retain their physical scope and verify hold. Do not silently impose this wrapper on ReadWrite/Full syntactic read candidates; absent actual proof, retain conservative effect/fresh authority. External/UDF effects and uncertain cleanup are not rollback proof.
- New queryRunId is the native durable operationId correlation. Bind the reserved executionEpoch through Accepted/dispatch_count0/version CAS before returning the first query.run receipt; dispatch accepts only the same bound epoch. Query-specific bounded MAC claims bind both public wire digest and native resolved digest plus owner/window/session/boot/revision/authority. Internal read-only admitted lookup preserves original operation/correlation/epoch after cache eviction and rejects changed payload; it never allocates another run/ticket or sends SQL. Missing expired results/cancel handles remain `WB_RESULT_EXPIRED`.

Keep64-run/64-stream/120s and original byte budgets; reclaim only finished run metadata and terminal+ACKed or explicitly expired result data through bounded LRU. Active work, unsettled cancellation and durable Unknown evidence are not evicted as successful work. Failure before dispatch must retain an honest unsent/failure state rather than an indefinitely accepted orphan. No new result.release command or automatic SQL replay is introduced.

- Per-import-batch child key binds parent+batchIndex+source byte/row range+digest; persist dispatch before each batch. Unknown stops subsequent dispatch; confirmed earlier batches remain. No restart automatic continuation. Internal active-job sequencing still requires fresh per-batch authorization.
