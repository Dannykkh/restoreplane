## Architecture and composition

- New crate restoreplane-workbench owns interactive session/execution/journal plus feature modules over that lifecycle. Reuse restoreplane-domain IDs and add canonical TypedCell/Workbench DTOs in a qualified context; add WorkbenchCommand in restoreplane-application, distinct from privileged ApplicationCommand. Do not duplicate generic command/secret frameworks. Current-user DPAPI is an explicitly named scope provider in existing restoreplane-secrets, with machine defaults unchanged.
- apps/console/src-tauri/src/lib.rs remains sole desktop composition. Add managed WorkbenchState and explicit workbench_request, a small result-notice Channel and bounded result.frames invoke pulls. existing service_request remains exact backup/control-plane bridge.
- Existing service ApplicationCommand gains only workbench.binding.authorize: scoped nonsecret canonical connect descriptor/target identity/revision/active-state receipt. No arbitrary SQL body, credential resolution or result rows cross it.
- Caller SID/logon/integrity/window are derived in Rust and named-pipe auth, never JS fields. Initial Workbench refuses elevated/high-integrity execution; existing backup/admin UI remains available. User launches standard-integrity Workbench for SQL.
- SQLite client-state.sqlite3 under verified current-user LocalAppData root with private ACL, single process owner/mutex + one journal actor. Additional app instance activates primary or refuses writes. Managed windows share coordinator but handles remain window-bound.
- Extend existing restoreplane-secrets with separately named CurrentUser protection (or typed scope API preserving Machine default); never infer scope from caller. Encrypt credentials and saved query content BEFORE SQLite/file bind. Elevated WorkbenchState is rejected before any journal/DPAPI directory/file initialization.
- Existing service metadata is not a complete connect descriptor: new authorize command creates canonical redacted descriptor/revision/epoch and rejects inactive/moved/revised resources.

## Authorization and session state
- Every new mutation dispatch gets a fresh authoritative service revision/owner check immediately before wire; cached lease may authorize reads only, max proposed30s revocation window.
- Read authorization receipt is in-memory, bound to issuing app nonce/principal/workspace/target/profile+endpoint+TLS revision and service boot/authority epoch. Not a portable persisted bearer credential.
- Service unavailability/lease expiry blocks new dispatch; status/cancel/rollback/disconnect remain permitted. COMMIT needs fresh authorization; expired-authority transaction offers rollback/status, never auto-commit.
- Already-dispatched SQL cannot be revoked by local lease invalidation. Profile invalidation retires session; cleanup preserves unknown if server disposition unproven.
- Reconnect creates new connection generation. Manual transaction never migrates. WorkbenchTransaction has distinct state from Query Run/statement states.
- Each physical connection also has Execution Epoch. Cancel targeting and run completion/next dispatch share a coordinator barrier. Next query cannot start until prior cancel is settled; uncertainty discards the physical connection. Client query IDs alone cannot make server backend cancellation safe.

## Driver and capability matrix
- Prefer existing tokio-postgres and rusqlite APIs/versions only after current security audit; introduce a maintained async MySQL/MariaDB driver with verified TLS/binding/stream/cancel behavior. Do not reuse CLI metadata stdout as a row protocol.
- Read/browse/type metadata/cancel/manual tx/verified edits/isolation are independently certified per engine+server+driver version; MariaDB remains a separate matrix row.
- TLS verify-full default, explicit user review for weaker mode; unsupported hostname/cert verification refuses. Local SQLite readonly session uses readonly file flags and restrictive authorizer/extension policy.
- SQL source sessions expose owner current-user OS/file authority; do not promise parser sandboxing. Full statements that read files/load extensions/procedures need explicit capability refusal or visible user authority, not an implicit secure sandbox.
- Grid edit supports complete ordinary nonnullable unique/PK identities with source provenance. Reject partial/expression/nullable/unresolved key or lossy type. Conditional comparison semantics must handle collation/precision; true version token gives stronger history detection than original values.
- MySQL/InnoDB/MariaDB lock+transaction and driver matched-row configuration, PostgreSQL locks, SQLite BEGIN IMMEDIATE/BUSY policy require live proofs. DDL implicit commits and nontransactional/trigger/external effects remain visible limitations.

## Operation state and durable delivery
- Operation Journal is local, user-owned; canonical key scope=(owner,workspace,target,kind,key), payload digest excludes plaintext storage. A replay returns existing operation identity, never a second remote dispatch.
- accepted -> dispatching (persist before wire) -> running -> commit_requested -> committed|rolled_back|failed|outcome_unknown. Single guarded version writer. Statement Outcome vector and containing transaction outcome are recorded separately; scripts can be partial/unknown despite final error.
- Only positive target evidence resolves committed/rollback. Operator Acknowledgment preserves original unknown outcome and permits a separately reviewed new intent/session; it does not rewrite history or automatically resend.
- Crash before dispatch marker may retire unsent intent; any dispatched/commit_requested write becomes unknown if evidence absent. Local fence/lease expiry never takes over a sent write.
- JournalEpoch + process BootEpoch constrain admission tokens. Native-issued attempt tokens expire after proposed24h; old/expired/foreign-epoch keys can only query existing status, never admit fresh execution. Terminal metadata retention proposed30days, unknown operations retained until conclusive resolution/explicit acknowledgment plus bounded tombstone policy. Quotas stop new admissions rather than prune active uncertainty.
- Restore/replacement/corrupt journal is not a way to resume commands; start write-disabled, fresh epoch, explicit reconciliation. Current-user store is not a target transaction coordinator.
- For this single-process local UI, operation state+monotonic version is the durable authority. UI notifications are best-effort/possibly duplicated hints; duplicate/old version is ignored, gaps/reconnect read operation.get/list from the journal. No additional durable Workbench UI outbox/inbox broker tables are required. Existing service notification outbox remains untouched. External durable consumers would require a separately reviewed outbox/inbox transaction contract.
- Ephemeral Result Batch sequence/ACK dedup is memory state with generation invalidation, separate from operation notifications; no durable body cache by default.

## Result protocol and resource accounting
- See ipc-spec.md for full command schemas. Reserve byte credit BEFORE enqueue/serialization, with bounded request queue and terminal/control reserve.
- Stream identity includes owner/window/workspace/target/session/connection generation/query/result/stream generation.
- highest contiguous ACK can advance only through actually sent sequences; duplicate/stale ACK returns zero credit, future/wrong-owner/overflow ACK refuses. Retire byte accounting exactly once. Gap recovery replays only retained bounded frames; otherwise explicit result-expired, never SQL reexecution.
- Inline cell/page/frame limits from spec are proposed gates. Encoded credits do not account for all decoded heap; additionally cap global JS/native retained caches, drafts, selection, tab count and serialization copies.
- Reads backpressure or deadline out; terminal states complete/capped/cancelled/interrupted/failed differ from transaction outcome. Terminal delivery has reserved capacity and status remains pull-queryable.
- Explicit page sort/filter starts new result generation. User buffer transformations occur only on explicit editor commands.

## Data consistency and write review
- Live-per-page browsing is the default. Frozen snapshot is bounded explicit per-engine transaction and must not mix fresh pages. Count semantics and schema freshness are visible.
- Typed Cells are canonical; display/copy-formatted/copy-exact are distinct. Unsupported/oversize types stay inspectable or explicit-export only, not editable from truncated strings.
- Verified Apply locks/rechecks target/schema/original row, uses bound values and catalog-quoted identifiers plus independent generated-statement structure gate, and verifies one matched row under the certified adapter.
- Reverted guarantee covers supported transactional effects; triggers/routines/nontransactional/external effects can exceed it and are disclosed/refused when unproven. No blanket all-world rollback.
- On conflict preserve draft, display original/current/draft, explicit refresh-basis requires new review. No silent retry/upsert/REPLACE/Undo.
- Generated edit uses its own transaction; active manual transaction blocks it. Query scripts retain ordered Statement Outcomes and report implicit commits/partial effects.
- CSV/JSON import uses bounded parser/parameterized inserts and explicit batch checkpoints; job cancellation can preserve committed batches. Export shown doesn't reexecute; export-all requires a declared fresh read/snapshot. Volatile or unproven query cannot be automatically rerun.

## Independent-review refinements
- Authorization linearization point is the service read transaction that admits the request. A later archive/revision does not retroactively revoke already-admitted SQL. Fresh pre-dispatch validation reduces stale admission; it is not a distributed atomic lock with the target server.
- Cached read leases are allowed only on adapter-certified server-enforced readonly sessions; every user SQL run otherwise requires fresh authorization regardless of parser verdict. Escape-capable SQLite authorizer/PRAGMA/ATTACH and server session setting changes are denied in readonly mode.
- Proposed time budgets: statement30s, lock-wait2s, snapshot60s, manual transaction idle30s; all hypotheses for live certification. Preserve target/user SQL and apply timeouts as session/driver settings, disclose effective values. No unbounded idle transaction.
- On uncertain cancel settlement, physical session discard does not prove rollback: write-bearing WorkbenchTransaction becomes outcome_unknown; proven read-only runs become interrupted/aborted_disconnected. Never send the next query on the retired socket.
- Multi-statement execution uses explicit reviewed statement boundaries and sequential individual dispatch where the adapter/parser proves them. An unseparable procedural block executes as one declared unit with conservative effect scope. Never split by semicolon strings or silently wrap a script.
- Import persists child batch operations keyed by parent job+batchIndex+source byte/row range+digest. Unknown batch immediately stops subsequent batches; earlier confirmed batches remain recorded. No restart auto-resume of writes.
- Fresh target authorization returns observed active backup/restore/maintenance state; new interactive writes/import/DDL refuse observed conflicts, with explicit recheck and lock-time bounds.
