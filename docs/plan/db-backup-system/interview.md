# Interview Transcript

## Soft Gate 1 — 공유 전제
- 목표: 랜섬웨어 내성 있는 DB 백업/복구 시스템. 개인 운영자.
- 범위: MVP → 수평 확장. Rust 단일 실행파일, Windows 구동.
- 성공 기준: "정해진 시간에 무인으로 백업되고, 랜섬웨어가 백업을 못 지우며, 필요 시 실제로 복원된다."

## Soft Gate 2 — 핵심 문제
- P1: 랜섬웨어가 백업본까지 암호화/삭제 → 복구 불가. (최우선)
- P2: DB별 접속 방식·버전 상이로 백업 자동화 어려움.
- P3: 자격증명(DB 비번, SSH 비번) 평문 노출 위험(깃허브 업로드 전제).
- P4: 무인 자동실행과 키 이식성의 충돌.

## 라이브 결정 (사용자 응답)

|---|------|------|
| Q1 | 백업 형태 | **논리 덤프만 (v1)** — PITR은 추후 확장으로 보류 |

| Q4 | 마스터 비번 분실 복구 | **복구 코드 발급** — init 시 오프라인 recovery key 1회 발급 |

## 추론 처리 (비차단, [inferred])
| 항목 | 기본값 | 근거 |
|------|--------|------|
| 사용자 규모 | 단일 운영자, 멀티유저/RBAC 없음 | 개인 프로젝트 |
| 인터페이스 | CLI 우선, GUI 후순위 | 무인 자동화가 목적 |
| 네트워크 토폴로지 | DB별 선택적 SSH 터널(직결 or 바스티온 혼재) 지원 | 서버 환경 다양성 |
| DB 규모 | 스트리밍으로 GB~TB 대응, 동시성 상한(예: 2~4) | 안전한 기본 |
| 복원 검증 대상 | 로컬 임시 인스턴스(Docker 또는 로컬 서버)로 test-restore | 별도 인프라 없다는 가정 |
| 실패 알림 | 로그 파일 + Windows 이벤트 + 선택적 webhook/email | 비차단, 확장 가능 |
| append-only 운영 | 백업 writer는 append-only, prune/lifecycle는 별도 격리 신원 | 리서치 권고 |
