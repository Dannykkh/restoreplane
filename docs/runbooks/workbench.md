# 데이터베이스 작업 사용 안내

현재 개발 소스의 Workbench 사용 계약이다. 기존 공개 `v0.1.0-rc.1`에 새 기능이 포함됐다는 뜻은 아니다. 실행한 검사와 남은 제한은 [구현 검증 장부](../plan/database-management-workspace/checklist-status.md)에서 확인한다. 엔진·서버 버전·열 형식별로 실제 연결이 표시하는 지원 여부를 따른다.

## 연결과 탐색

1. Console을 일반 Windows 사용자 권한으로 실행하고 Workspace와 등록한 Database Target을 선택한다. 관리자 권한 Workbench는 사용자 상태나 자격증명을 초기화하기 전에 거부된다.
2. `데이터베이스 작업`에서 별도의 DB 사용자 자격증명을 입력한다. 백업 서비스의 비밀정보를 가져와 연결하지 않는다. 서버 인증서와 호스트 이름 검증을 통과해야 연결된다.
3. 실제 주소·데이터베이스·DB 사용자·원본/복원 대상 구분을 확인한다. 대상이나 연결 세대가 바뀌면 이전 검토와 결과를 새 연결에 적용하지 않는다.
4. 스키마와 테이블을 찾아 조회한다. 필요한 페이지만 가져오며 만료된 페이지는 명시적으로 다시 조회한다. 고유 키 없는 미리보기, 조회 상한, 전체 수 미확인과 조회 시각을 확인한다.

테이블의 `행 조회`를 기본 작업 화면으로 사용한다. `관계도`와 `SQL 작성·검토`는 별도 화면이며, 테이블을 선택하는 동작이 SQL 초안을 자동 실행하지 않는다. 실제 대상·모드·트랜잭션 상태는 화면 위에서 확인하고 자세한 대상 정보는 `전체 대상 보기`로 연다.

일반 페이지는 서로 다른 시점의 데이터를 볼 수 있다. 지원 연결에서 명시적으로 시작한 스냅샷만 표시된 격리 수준과 만료 시각까지 유지된다. 만료 시 일반 조회로 조용히 전환하지 않는다.

현재 생성 편집·가져오기·스냅샷의 인증은 SQLite3.54.1, MySQL8.4.13, MariaDB11.4.13-MariaDB-ubu2404와 검증한 PostgreSQL17.11 Alpine 빌드의 정확한 서버 버전 문자열에 묶인다. 버전이 같아도 일반 기본 테이블·키·자료형·서버 설정 검사를 추가로 통과해야 한다. 이 목록은 임의 SQL의 모든 효과나 다른 서버 빌드를 인증하는 목록이 아니다.

현재 네이티브 드라이버는 셀 상한64KiB를 넘는 원문을 LOB 핸들로 제공하지 않는다. 큰 값의 별도 조각 읽기(`result.value.get`)는 미지원이며, 상한 초과나 미지원 형식을 완전한 원문으로 표시·편집·내보내지 않는다.

## SQL과 트랜잭션

`SQL 작성·검토`의 원문 편집기에 SQL을 입력하고 아래 결과 영역에서 해당 실행의 결과를 확인한다. 연결 엔진에 맞춰 PostgreSQL·MySQL·MariaDB·SQLite 문법을 구분하며, 알 수 없는 엔진에는 일반 텍스트를 사용한다. `Ctrl+Space`는 현재 선택한 스키마·테이블 범위의 이름을 제안한다. 제안을 선택해도 SQL을 실행하지 않는다. 이름 제안은 권한이나 최신 스키마를 보장하지 않으므로 실제 실행 전 검토가 필요하다.

처음에는 읽기 전용 모드를 사용한다. 변경하려면 실제 대상을 확인해 모드를 전환하고 SQL 검토 후 실행한다. 검토한 원문을 실행하며 Explain과 실제 실행을 수반하는 Explain Analyze를 구분한다. 거부된 문장을 백업 서비스로 우회하지 않는다.

생성한 실행 계획 SQL도 전체 문장을 확인한 뒤 별도로 검토한다. PostgreSQL은 실행 계획과 실행 분석, MySQL은 실행 계획과 `EXPLAIN ANALYZE FORMAT=TREE`, SQLite는 `EXPLAIN QUERY PLAN`, MariaDB는 실행 계획 도우미를 제공한다. 현재 SQLite·MariaDB의 실행 분석 도우미는 제공하지 않는다. 실행 분석은 Full 모드와 실제 실행 경고 확인을 거치며 편집 원문에 접두사를 덧붙이지 않는다.

수동 트랜잭션은 하나의 실제 연결에 유지된다. COMMIT 접수와 COMMIT 완료 확인은 다르다. 서버가 확정한 오류 뒤에는 표시된 롤백 필요 상태를 처리한다. 중지·연결 종료·재접속만으로 롤백됐다고 판단하지 않는다. 재접속은 이전 트랜잭션을 복구하지 않는다.

초안과 결과는 기본적으로 메모리에만 둔다. 명시적으로 이름을 붙여 저장한 쿼리만 현재 Windows 사용자에 묶인 암호화 저장을 사용한다. 다른 Windows 계정에 자동 이식되는 저장소가 아니다.

초안은 최대8개, 합계 UTF-8 1MiB까지 유지한다. 상한을 넘는 입력은 원문을 자르지 않고 거부한다. 초안을 수정하면 이전 검토는 무효가 되므로 다시 검토해야 한다. 화면 전환만으로 초안을 다시 실행하거나 수신 중인 결과를 새로 요청하지 않는다.

## 행 변경

지원되는 일반 기본 테이블에서 변경 초안을 만든다. 뷰·조인·불확실한 키·미지원 형식은 읽기 전용 이유를 확인한다. 빈 문자열, SQL NULL, 생략한 기본값을 구분하고 실제 대상·생성 문장·값을 검토한다.

한 검토는 명시된 행/바이트 상한 안의 단일 트랜잭션이다. 원본 행이나 구조가 달라졌으면 초안을 보존하고 충돌을 표시한다. 표시된 현재 값도 관측 시점의 값이다. 다시 적용하려면 새 조회와 새 검토가 필요하다.

## 가져오기와 내보내기

네이티브 파일 선택 창으로 파일을 고르고 형식·원본 열 순서·대상 열 매핑을 검토한다. 같은 이름의 열도 순서로 구분된다. 전체 파일을 화면에 적재하지 않으며 잘못된 형식·손실 변환·상한 초과 행을 조용히 건너뛰지 않는다.

가져오기 배치는 독립 트랜잭션이다. 앞서 확인된 커밋은 후속 실패나 취소로 되돌아가지 않는다. 결과가 확인되지 않은 배치가 있으면 후속 전송을 중단한다. 재개는 파일·대상·구조·기존 기록을 새로 검토한 뒤 전송하지 않았음이 확인된 범위에만 가능하다. 재시작 뒤 자동으로 이어 보내지 않는다.

현재 가져오기 재개는 실제 서버·DB 정체성을 입증한 PostgreSQL과 인증된 로컬 NTFS SQLite만 지원한다. MySQL/MariaDB는 최초 가져오기를 지원해도 같은 작업의 재개는 지원하지 않는다.

내보내기는 화면의 정확한 보유 범위와 명시적인 새 읽기를 구분한다. 화면 범위 내보내기는 원래 SQL을 다시 실행하지 않는다. 그 파일이 완성돼도 원래 조회의 상한 도달·수신 중단 상태나 테이블 전체의 완전성을 바꾸지 않는다. 새 읽기는 대상·시점·일관성을 확인하며 입증되지 않은 SQL을 자동 재실행하지 않는다.
내보내기에 전달해 접수된 전용 스냅샷은 해당 파일 작업이 종료할 책임을 맡는다. 성공·실패·취소 뒤에도 연결을 붙잡아 두지 않으며, 정리를 확인하지 못하면 정상 완료로 표시하지 않는다.
새 파일 읽기는 최대100만 행·인코딩된 원본1GiB·300초의 별도 운용 상한을 사용한다. 화면 SQL 조회의10만 행·64MiB·30초 및 메모리 상한을 늘리는 설정은 아니다. 스냅샷의 남은 기한/최대60초가 먼저 끝나거나 총량 상한에 도달하면 부분 파일로 남는다.

CSV/TSV는 SQL NULL을 `\N`, 빈 문자열을 빈 값으로 구분하며 실제 역슬래시로 시작하는 텍스트에는 역슬래시를 하나 더 붙인다. 기본 수식 방어 정책은 표시를 바꿀 수 있다. 정밀 숫자·바이트·시간 형식의 정확한 표현은 지원되는 형식 포함 JSON을 사용한다. 잘린 미리보기나 미지원 값을 원문처럼 내보내지 않는다.

완전한 해당 범위/새 읽기와 쓰기·동기화·최종 파일 확정을 모두 확인해야 파일이 완료된다. 실패·취소 시 부분 파일의 위치와 상태를 확인한다. 부분 파일에도 실제 사용자 데이터가 들어간다. 정리는 해당 작업의 부분 파일만 명시적으로 요청하며 완료 파일을 자동 삭제하지 않는다.
파일 정체성에 의존하는 복원 검사와 파일 확정/정리는 현재 인증한 로컬 NTFS 범위만 허용한다. 다른 파일시스템을 확인 없이 같은 지원 수준으로 취급하지 않는다. 파일 삭제 후 재생성까지 영구히 동일성을 보장하는 기능은 아니다.

## 백업과 복원 연계

선택 테이블을 기존 Backup Scope로 넘길 때 서비스가 대상과 최신 구조를 다시 확인한다. 일부 테이블 조사 결과는 전체 DB 목록을 대체하지 않는다. 새 선택 Scope 하나에는 새 조사가 대응하므로 별도 Scope에는 다시 조사해야 한다.
현재 Workbench의 선택 Scope 전달은 인증한 PostgreSQL 경로를 기준으로 한다. 기존 MySQL/MariaDB 백업 어댑터의 미지원 인증서 검증 모드를 더 낮은 TLS 설정으로 바꿔 전달하지 않는다. SQLite의 명시적 테이블 Scope도 지원하지 않으며 전체 DB 백업으로 자동 확대하지 않는다. 기존 백업 기능의 지원표와 Workbench 연결·연계의 지원표는 각각 확인한다.

변경 전 백업은 별도의 작업과 근거다. 백업 완료 이벤트가 SQL을 자동 실행하지 않으며 백업·일반 SQL을 하나의 분산 트랜잭션이나 즉시 Undo로 묶지 않는다.

복원의 읽기 검사에서는 새로 등록한 복원 대상을 직접 선택한다. 네이티브가 완료 근거와 실제 대상 정체성을 대조한 뒤 읽기 전용 세션을 연다. 불일치·미지원·권한 거부 때 원본으로 대신 연결하지 않는다. 복원 검사용 세션은 쓰기 모드로 올릴 수 없으며 재접속 때도 검증을 유지한다.
같은 이름이나 같은 내용만으로 복원 대상을 승인하지 않는다. 해당 엔진의 완료 근거와 실제 instance/file 정체성을 제공할 수 없는 경우에는 읽기 검사 진입도 거부한다.

## 결과를 확인하지 못했을 때

`작업 기록`에서 해당 작업과 문장/배치별 상태를 확인한다. 응답이 없다는 이유로 같은 변경을 새 요청으로 다시 보내지 않는다. 확인 불가는 성공·실패·롤백 중 하나로 추정하지 않는다.

운영자의 확인 처리는 실제 DB 효과의 증거를 바꾸지 않는다. 원격 DB에서 상태를 독립적으로 확인하고 새 변경은 별도 의도로 검토한다. 가져오기의 확인 불가 배치는 운영자 확인 후에도 같은 부모 작업에서 재전송하거나 건너뛰어 재개할 수 없다.

사용자 상태 저장소의 손상·삭제·이전 상태 교체 오류를 자동 초기화나 파일 삭제로 우회하지 않는다. 남은 근거를 보존하고 명시적인 복구가 필요하다. 이 보호는 같은 사용자가 DB와 독립 무결성 근거 전체를 악의적으로 함께 되돌리는 상황까지 보장하지 않는다.
